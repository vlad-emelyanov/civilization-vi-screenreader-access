# Features and architecture

Current behaviour of the mod, by area. Present tense, no history (git log has that). Read `CLAUDE.md` and `docs/keynav-guide.md` first; open work is in `docs/backlog.md`, engine facts in `docs/engine-notes.md`, wording rules in `docs/speech-guidelines.md`.

- **Keys:** this file names only the entry key of a feature. The full key list, with the current bindings, is `ScreenReaderAccess/Assets/UI/Accessibility/HelpText.lua` (canonical, shown in game with Control+H). Do not copy key maps here.
- **Turn loop:** Enter = the game's Next Action. It selects the next unit that needs orders, opens the production/research/civic chooser, and ends the turn when nothing blocks. Everything below fills the gaps in that loop. N says what Enter will do.
- **"Unverified"** below means: no regress script covers it and it was never seen in the real game (code and unit tests only). Everything else has a `test/regress/*.txt` script or was seen in play.
- Pure wording lives in `Accessibility/*Text.lua` files with `test/lua/test_*.lua` tests. Files named `Foo_SRA.lua` in `UI/Replacements/` replace a game script with `ReplaceUIScript`; other overrides are `ImportFiles` copies (pristine commit first, then marked `ScreenReaderAccess` blocks). Why each method: `docs/engine-notes.md`. A `print( "ScreenReaderAccess: X copy loaded" )` in `Lua.log` proves a copy loads.

## Architecture

- **Hub context `InGameAccess`** (`UI/Additions/InGameAccess.{xml,lua}`, added with `AddUserInterfaces`): owns global hotkeys, the map cursor, modes (list navigation) and event-driven announcements. `InGameAccess.lua` (~360 lines) is wiring only: includes, Enter fallback, input handler, update loop, `Initialize` with the registered actions and events. `Hub` (global, defined there) holds what stayed in it. Prefer the hub over editing game files.
- **Hub modules** `Accessibility/Hub*.lua`, included just before `Initialize`, registered in `InGameActionData` only. Each defines ONE global table with its functions and state; cross-module calls go through the tables (`HubCore.SayResult( text )`); a name used by one module stays file-local. `test/lua/test_hubmodules.lua` loads the hub and all modules against a stub and runs `Initialize`.

| Module | Owns |
|---|---|
| `HubCore` | shared helpers (`Safe/Listen/After/SayResult`), `OpenMode/CloseMode`, shared `m_` state, speech hold queue (`Announce`, `UpdateSpeech`) |
| `HubCursor` | map cursor, plot speech, jumps, X scan of foreign units, select at cursor, Control+K |
| `HubTargets` | target modes (enter/confirm/cancel), attack previews, attack and capital keys, F8 reports toggle |
| `HubAnnounce` | N "what is next", selection / turn / ready announcements, loyalty and hint suffixes |
| `HubSettle` | X browsers: settle spots, builder tiles, activation tiles of great persons and others |
| `HubPlacement` | district / wonder placement browser |
| `HubMenus` | Tab unit actions menu, V diplomacy list, Control+R standing |
| `HubRegions` | top panel (Control+Y), notifications (Control+N), Control+G, Control+W |
| `HubMessages` | messages history (Control+M); `HubCore.Announce` logs into it |
| `HubCityReport` | Control+I city report and city management sub-lists |
| `HubEvents` | order results, combat lines, map events |
| `HubEnemies` | turn-start "what did the enemies do" line |
| `HubPlaces` | J places list (incl. Threats, Blind spots, Foreign lands), M send-a-unit lists |
| `HubOverview` | Shift+J area overview |
| `HubHelp` | Control+H help list (text: `HelpText.lua`) |
| `HubGamepad`, `HubPad`, `HubLenses`, `HubScreens` | controller buttons, the LB/RB ring and its two ring-only lists |
| `HubMultiplayer` (+ `MultiplayerText`) | in-game multiplayer: chat, turn timer warnings, players dropping out |
| `HubPins` (+ `MapPins`, `UnexploredScan`) | Control+P map pins as bookmarks; data layer of the places list categories Pins and Unexplored |

- **Reusable logic in `Accessibility/`** (`PlotDescription`, `SettleScan`, `PlacementScan`, `BuildScan`, `BlindSpots`, `DistrictAdvice`, `ResourceTech`, `StandingText`, ...). A helper a front-end file includes must be in BOTH `FrontEndActionData` and `InGameActionData`.
- **Game file overrides only where the data or callbacks live in that context** (UnitPanel, ProductionPanel, choosers, NotificationPanel, ActionPanel, screens). Check `DLC/Expansion1|2/UI/Replacements`: with Gathering Storm, `TopPanel` is replaced by the XP2 copy and `UnitPanel_Expansion2` includes `_Expansion1` which includes `UnitPanel`. Override the file that holds the code and confirm with a load print.
- **Cross-context calls** go through `LuaEvents.SRA_*`; pass plain data, never functions.
- **Input order:** the hub's `SetInputHandler` runs before `WorldInput` and `ActionPanel`; consuming KeyDown and KeyUp of a key in a hub mode is all a mode needs (a consumed Enter does not fire Next Action). `Keys` codes: engine-notes.
- **Hub context facts:** the hub calls `ContextPtr:SetHide( false )` first (a hidden context gets no input actions). The cursor plot is put at screen centre with `UI.LookAtPlotScreenPosition( x, y, 0.5, 0.5 )`; the real mouse follows 0.8 s after the last move, after `LuaEvents.SRA_CursorPlot( plotIndex )` so `PlotToolTip` does not read the plot twice.
- **End-turn text** (N) is read from the ActionPanel label `/InGame/HUD/ActionPanel/EndTurnText` (`ContextPtr:LookUpControl`), so expansion blockers are covered. N and Enter share one intent (`EnterIntent`). The label lags a moment behind a unit that just arrived ("Next turn" while the unit needs orders): N then says "Unit needs orders: ..." (`HubAnnounce.LabelHidesReadyUnit`) and the Enter fallback speaks the silently re-selected unit. While a read-only list (top panel, city report, notifications, messages, help ...) is open N says "A list is open, Enter opens nothing in it. Escape closes it ..."; moving the map cursor closes such a list (`HubCore.CloseReadOnlyMode`), and Enter's "Nothing to open here" names Escape. Not reproduced: the reported case of a cursor move after which a list was still open (the plain-arrow cursor keys of this install are taken by the list, so the lists stayed open only by hand).
- **Speech:** key results interrupt; events (new turn, notifications, combat) use `nointerrupt`. A popup that speaks sends `LuaEvents.SRA_SpeechHold( name, true|false )`; `HubCore.Announce` queues selection/turn/combat lines while a hold is active (max 6, deduped, holds expire after 60 s, cleared at turn end and load) and speaks them 0.4 s after the release. When the hold begins while the last announcements are probably still speaking, the popup's first line goes out as NOINTERRUPT (one-shot flag `ExposedMembers.SRA_QueueBehindUntil`, shared by all UI contexts, expires after 2 s; `SRRequestQueueBehind` / `SRTakeQueueBehind` in `ScreenReader.lua`), so it queues behind them: nothing is cut off, nothing replayed. Key hints in spoken text use `SRKey` / `SRPadHint` / `SRKbHint` (see Controller).
- **Modes:** the unit menu, V list, X browsers, top panel, notifications, city report, places, overview and help are `OpenMode/CloseMode` entries of one `m_mode` (opening one closes the other); target modes refuse to open one; selection change, turn end, load and player change close it silently. Lists use `KeyNavList`.
- **Hub limits:** a Lua chunk holds 200 locals, so new state goes into module tables. `rawset` and (in `GameCore_Tuner`) `pcall` do not exist in the Civ Lua sandbox. Listeners are registered with `SRListen` and removed by `SRUnlistenAll()` on shutdown; a production panel open during a hot reload goes dead (reopen works).

## Front end

Path that works end to end: Main menu, Single Player, Create Game or Advanced Setup (all options, players, add/remove AI), Start Game, load screen, Enter begins. Files: `Assets/UI/Frontend/{MainMenu,AdvancedSetup,LoadScreen,LoadGameMenu,FrontEndPopup,StagingRoom,JoiningRoom}.lua`, `Options.lua`; reference implementations `MainMenu.lua` and `AdvancedSetup.lua`.

- **Setup pulldowns:** mod-side selection mode (Enter opens, Up/Down/Home/End say "value, i of n", Enter applies, Escape cancels). The leader / civilization pulldown (`KeyNavSetup_LeaderItem`, Create Game and Advanced Setup player rows) reads "Pericles, Greece, 23 of 33" (civilization added from `GetPlayerInfo`, left out for Random entries and when the leader name already holds it) and Space reads the game flyout: civilization ability, leader ability, unique unit / building / district / improvement, one line each. Map Select and Multi-Select popups are navigable. Exit confirmation popup works.
- **Load Game** (also in game; `LoadGameMenu.lua` and `LoadSaveMenu_Shared.lua` are registered in both action data): "N saves", Up/Down over saves (name, leader, civ, turn, date, "i of n"), Tab between groups (saves / options / buttons), Space reads full details, checkboxes, sort, Delete opens a confirmation. The in-game Save Game screen (`Menus/SaveGameMenu.lua`) edits the name through `KeyNavEditBox` and asks before overwrite/delete; "Game saved" comes from `Events.SaveComplete`.
- **Options** (every tab): Up/Down over tabs and Confirm/Restore/Back, Enter enters a tab, Left/Right change pulldowns and sliders (the mouse is parked off sliders). Key Bindings: Tab = next category, Enter rebinds, Delete clears; the engine records a rebinding only if the input handler returns false for the key. Confirm/Reset popups (incl. the 15 s countdown) work with Up/Down/Enter, Escape = last button.
- **Text fields** (`KeyNavEditBox.lua`; seed, LAN name, webhook URL, pedia search, chat): "label, edit, value|blank, Enter to edit"; typing is echoed; Enter commits, Escape restores. Engine facts: while an EditBox has focus the context's input handler gets no key events; Enter fires the commit callback; Escape reverts the text, fires the commit callback, and its KeyUp still reaches the context (the helper swallows it); the HasFocus callback gets the control, not a boolean; characters rejected by `SetNumberInput( true )` give no callback. `ChatEntry` has KeepFocus, so Escape only reverts the text: option `cancelOnRevert` treats an all-at-once revert as Escape (heuristic: Escape after one typed character or in an empty box does not end the edit; Enter says "Nothing sent").
- **Staging Room** (host side; client untested): Tab cycles Players / Buttons / Tabs; Enter or Right opens a player row's controls (slot, leader, team, color, difficulty, kick, add); Ready toggles ready or cancels the countdown; S reads the launch status; Tabs: Game Summary, Friends (Invite through the Steam API); C types a chat message, H reads the last 50 lines; incoming chat is spoken without interrupting.
- **JoiningRoom:** announces each status, Escape cancels; failures arrive as the FrontEndPopup.
- **Load screen** (`LoadScreen.lua`, paragraph logic in `Accessibility/LoadParagraphs.lua`): one short line, "Loading Rome, Trajan. Up and Down read the civilization details, 6 paragraphs" (no hint when the list is empty), so the game's narrator is not talked over. Nothing else is read on its own. Up/Down/Home/End move and interrupt ("text, n of N"; "Last paragraph" / "First paragraph" at the ends, no wrap), Space (Y) reads the current paragraph again (the first when none is focused); D-pad works through `Gamepad.WrapInput`. Paragraphs in screen order: civ and leader, era, leader info, then "Name: description" per ability, unique unit and unique building (normal case; units and buildings use the full game description, `GetLeaderUniqueTraits( leaderType, true )`, not the screen's short "A unique land unit"). `CleanTextForSpeech` turns no-break spaces, ellipses, curly quotes and dashes into plain characters (the speech pipeline said "?" for them). The input handler is set when the content is ready (before loading ends) and keys keep working until Enter. Enter begins the game; "Begin Game. Press Enter to start." is spoken once loading is done. Verified: Up/Down also work during loading, before "Press Enter to start" (`load-screen-paragraphs`).
- Known gaps / unverified: the leader pool picker and city-state picker windows (Enter opens them; the leader pulldown of a player row has its own list, see Setup pulldowns); Gathering Storm welcome popup; in-game multiplayer game parameters; Switch UI Layout popup; Staging Room client side.

## Map cursor and turn flow

- **Cursor:** Shift+Arrows move it and speak the plot (`PlotDescription.lua`). Order: a lens value (when a lens is on), a strategic or luxury resource with its class ("Iron (strategic), needs Bronze Working"), the position, then city, units, terrain, feature, bonus resource, river/coast, improvement, district, owner, yields ("unexplored"/"fogged"; fogged plots speak what the game's own tooltip does, units only when visible), and last the selected unit's suffix ("can settle", "Builder can build: Quarry"). The position is relative to the selected unit or city ("3 tiles north-east"), and after a jump also from the nearest city (below); a plot without such a resource starts with the position. I = detailed description. `.` = cursor to the selected unit/city. Control+Shift+Arrows jump 5 tiles. K selects your unit/city on the cursor plot (again: the next one there), Control+K walks all your units, Backslash = capital ("Capital: Rome"), always spoken.
- **Jumps** (notification Enter, X scan, places list) also say the position from the nearest own city ("7 tiles north-west of Rome"); single steps do not. The same position text (`HubAnnounce.PositionText`) is used on unit selection and in the places lists: when the nearest city of another player (civilization, city-state or free city, only cities whose plot we have revealed) is strictly closer than our nearest one, it comes first with its owner: "1 tile west of Seoul (Korea), 4 tiles east of Aquileia"; inside a foreign city "in Seoul (Korea)". A city-state named like its city is not repeated in brackets.
- **PlotToolTip** (override) drops `-----` lines, stays quiet for a plot the cursor already read and speaks only for a mouse that really moved.
- **Turn flow:** "Turn 5, 3600 BC" at turn start; "Turn ended" (only if the turn changed or the local player is inactive); "Turn not ended: <blocker>" when the engine reactivates the turn (unit needs orders after queued moves, World Congress waiting). Load announces once the turn is running; a unit selected during the load is announced after "Turn 1". A ready watch says "All done. Enter ends the turn" once per ready phase. Enter on an exposed settler/builder asks once more. Multiplayer (simultaneous turns), UNVERIFIED, MP only: after readying, the action panel says "Waiting for players" / "Waiting for NAME" and the turn stays active, so the mod says "Turn ended, waiting for other players" (and never "Turn not ended: Waiting for ..."); Enter on that label un-readies (`ACTION_UNREADYTURN`) and `Events.LocalPlayerTurnUnready` makes the mod say "Turn resumed" (interrupting), cancel its pending end-of-turn checks and re-arm the ready watch ("All done" follows once the label says "Next turn").
- **Selection announcement:** unit name, moves, activity ("exploring", "fortified", ...), position suffix ("in Rome", "1 tile east of Aquileia"), hints (promotion "Shift+U", upgrade with cost, escort, civilian danger), corps/army names, carrier cargo. City selection: name, population, production, growth, loyalty. A selection event for the unit already selected says nothing.
- **Loyalty warning:** after the Turn line, one line per own city whose `GetConversionOutcome` is LOSING_LOYALTY (the game's own map-warning condition) and whose `GetTurnsToConversion` is 1..8, soonest first, at most 3, then "and N more": "Lugdunum loyalty 62, falling 19 a turn, lost in 4 turns. Control+I on that city for why" (verified: `loyalty-warning-turn-start`; `HubAnnounce.SpeakLoyaltyWarnings`; the key is the current KeyNavCityReport binding). It lands in the messages history.
- **Spy arrival:** a destination whose travel plus establish time is 0 says "arrives next turn" (verified: the spy stays in its city until the turn change and stands in the target city at the start of the next turn).
- **Confirm then result:** the spy and trade choosers raise `LuaEvents.SRA_ConfirmPending` (the trade result event does too) on the confirming Enter; for 3 s or until the result line speaks the hub's Enter watch (`Hub.EnterFallback`) stays silent, so no stale "<Unit>, needs orders" line precedes "Trader moved to ..." / "<Spy> travels to ...". Modal choosers answer Tab ("No tabs here") and F1-F12 ("Close the list first, Escape closes it") via `KeyNavList_SayUnhandledKey`. Verified by `trade-route-confirm-result-only` and `spy-confirm-result-only`; after a cancelled route list, Enter on the map gives the normal next-action speech. While a chooser mode (`SPY_TRAVEL_TO_CITY`, `SPY_CHOOSE_MISSION`, `MAKE_TRADE_ROUTE`) is the interface mode, `Hub.EnterFallback` stays silent too (`HubAnnounce.ChooserOwnsEnter`), so the first Enter on a destination says only "Send X to Y? ...". Arrival time 0 is spoken "arrives this turn" (never "0 turns").
- **Enemies:** "Barbarian Scout spotted, 3 tiles south-west of Xi'an" (once per unit per 10 turns, max 4 per turn). `HubEnemies` speaks one turn-start line comparing hostile units within 6 tiles of a city or 3 of a unit with the last snapshot. A barbarian scout that has seen us (`GetBarbarianTargetPlayer() == us`) raises an alarm; 2+ barbarian soldiers near a city give a raid line; civilians near a hostile soldier a danger line; camps destroyed are counted once. Scenario-created scouts are never flagged (use a fixture's own).
- **Exploring units** (`HubPlaces.ExplorerStopped/CheckExplorers/ExplorerUnits`, `HubEnemies.ExplorerLines`): a unit the game offers for orders is no longer "exploring" (activity text drops the flag, `IsReadyToSelect`, see engine-notes). 2.8 s after the turn start "Scout stopped exploring, Danger, Barbarian Warrior 1 tile east, needs orders" (reason only when a hostile is within 3 tiles). At turn start "Your exploring Scout is 2 tiles from a Barbarian Slinger. Tab for actions, any order takes it over" for a visible hostile soldier or a remembered camp within 2 tiles, once per unit and enemy per 5 turns. Unverified: a stop by the game itself.
- **City in danger** (`HubEnemies.SpeakCityDanger`, after the threat lines at turn start): per own city, hostile soldiers of civilizations at war with us (not barbarians: they have the raid line) that are visible within 3 tiles. With 2+ units or any siege/ram unit and a summed strength above 1.5 times the city's defence, or a damaged city with an enemy next to it: "Rome in danger: 3 units of Egypt within 3 tiles, city strength 28, walls 50 of 100. Control+I for the city" (current KeyNavCityReport binding; ", including Catapult" for siege). At most 2 cities per turn, a city again only when the unit count rises or its health (garrison plus walls) falls (`CityDangerDecision/Repeat/Text`, `test_hubenemies.lua`). Verified (`city-danger-warning`: the scenario declares war with `Players[other]:GetDiplomacy():DeclareWarOn(0, WarTypes.FORMAL_WAR, true)`); the 1.5 times threshold is still a guess.
- Known gaps / unverified: scout "escaped" / "killed" lines and "Raid continues" over real turns; the city-in-danger thresholds (1.5 times) are a guess; auto-explore end is not announced.
- **Multiplayer in game** (`HubMultiplayer.lua`, wording in `MultiplayerText.lua`, tests `test_multiplayertext.lua`), UNVERIFIED, network games only: (1) chat: `Events.MultiplayerChat` (what the game's chat panel listens to) is spoken without interrupting as "Anna: text", "Anna, team: text" or "Anna, private: text" once the load is done (the Staging Room speaks the chat before the game, that screen is gone then, so nothing is said twice), and logged in the messages history (Control+M). The local player's own echo is only kept. Control+T (`KeyNavChat`) opens a list "Chat, 12 messages": "Type a message" first, then the history newest first. Enter on "Type a message" shows the hub's hidden `SRChatBox` EditBox (`InGameAccess.xml`), `KeyNavEditBox` types into it ("editing message"), Enter sends through `Network.SendChat( text, CHATTARGET_ALL, -1 )` ("Message sent"; empty: "Nothing sent"), Escape says "Message cancelled". Everybody gets it; whispers and team chat commands are not available. In single player, hotseat and Play By Cloud: "Chat is for multiplayer games". (2) turn timer: `Events.TurnTimerUpdated( elapsed, maxTurnTime )` (the action panel meter's event; maxTurnTime <= 0 without a timer, then the handler returns at once) gives "1 minute left in the turn", "30 seconds left in the turn", "10 seconds left in the turn" without interrupting, only while the local turn is active and the action panel does not say "Waiting for players"; the top panel list (Control+Y) has "Turn timer: 1 minute 20 seconds left" (from the last reading, nothing when it is older than 5 s). (3) players dropping out: the status panel override already speaks "<name> connected / disconnected / kicked" (`StatusMessagePanel.lua`); the hub adds those lines to the messages history and, 1.5 s after `MultiplayerPostPlayerDisconnected`, says "<name> is now played by the computer" when the slot is a computer slot or no longer human (the game shows nothing for an AI takeover; the test of the slot is a guess).

## Units and orders

- **Unit details** (Shift+I, `KeyNavUnitDetails`, `UnitDetails.lua`, `HubCursor.SpeakUnitDetails`): every visible unit on the cursor tile (military first), else the selected unit, else "No unit here". Own unit: "Warrior, level 1, 5 of 15 experience, promotion available. Strength 20. 2 of 2 moves, sight 2. Health 100 of 100. Promotions: Battlecry, Tortoise." Ranged/bombard add "Ranged 25, range 2"; civilians moves, charges and health only when hurt; religious units strength and spreads left; great people action charges and passive effect name. A foreign unit says only owner, level, strengths, health and promotions. Works in target modes (an input action, the mode stays). The detailed tile text (I) adds "strength 15, ranged 25" to a foreign unit and "strength 28, walls 100 of 100, health 200 of 200" to a visible city. Unverified in game (`unit-details`): sight is the unit type's base sight, the great person passive name call.
- **Tab menu** (`HubMenus`, from UnitPanel's own action table via `LuaEvents.SRA_RequestUnitActions / SRA_UnitActions / SRA_RunUnitAction`; `Panels/UnitPanel.lua`): "Move To, key M, 1 of 6", disabled ones "unavailable: reason" and listed after all available ones (stable partition, `HubMenus.AvailableFirst`; the numbering follows), Space = tooltip. The mod's browsers are the first entries. Results are spoken from `UnitOperationStarted` (so game hotkeys speak too); Automate Exploration and Fortify Until Healed fire only `UnitOperationAdded`.
- **Reasons:** a disabled action or hotkey says why: no moves, already built, not possible on this tile, stacked-unit reason for Skip/Fortify/Sleep, "Danger" for exploring, ranged "no enemy it can target in range" (derived; a unit without a ranged strength says "<Unit> has no ranged attack", only a ranged unit gets the two-military-units city reason), no moves with only Delete Unit left (the Tab menu opens "<Unit> actions, no moves left"), city "needs walls" / "already attacked this turn" (hedged). Some units (an unescorted settler, a besieged unit) get no skip/sleep from the engine: Enter says "Cannot skip: ... move it, found a city or delete it".
- **Promotions:** "Promotion available, Shift+U" on selection; `Popups/UnitPromotionPopup.lua` lists every promotion of the class (have / available / locked: needs A or B); Enter promotes ("Promoted: X"). **Upgrade** (U): result or reason; selection hint "Upgrade to Pikeman available, 120 gold, U".
- **Great people** (U): "<name> activated: <effect>"; on the wrong tile "Cannot activate X: must stand on a completed Campus district. Nearest: Rome's Campus, 1 tile north-west"; generals' Retire asks first; Transfer to Another City is a target mode for non-traders.
- **Builders:** Tab menu drops tile-impossible entries, Remove Improvement warns before destroying ("Enter again to confirm"), cursor text ends "Builder can build: Quarry". Repair of pillaged items: "Repair X" / "Repairing X", reasons incl. enemy on the district. The tile browser is never silent: with nothing to improve X says "No tile to improve near Knossos", the Tab entry "Browse tiles to improve" is unavailable with that reason (`HubSettle.NothingToImproveReason`, from the scan cache), and an error while opening says "Could not list the tiles to improve". The original silent X in fixture bug-builder-x-silent-knossos did not happen again on a fresh load (5 tiles listed); the cause is unknown.
- **Also:** escort (Shift+E; selection says "escorted by", a civilian moving alone near danger is warned); embarked land units ("Arrived, embarked"); trade outcomes come from `LuaEvents.SRA_TradeResult`.
- Known gaps / unverified: promotion-tree units (only the game's tree opens); Name unit; corps -> army and fleet names in real play; WMD/ICBM and PRIORITY_TARGET still click; coastal raid / sacrifice / hero commands ported by reading only; a city production auto-swap is not announced.

## Target modes

- Entered by M, R, W, Tab menu items or any key that sets an interface mode (`HubTargets`). Opening line "Move to: choose a tile ..." (attack mode, ranged, air and city ranged attack: ONE line when the first target is known, "<Label>: <target name and owner>, <position>, <preview>. X next target, Enter attacks, Escape cancels" (`HubTargets.BeginOpening` / `CombatText_OpeningLine`; nothing in range: "<Label>. No enemy in range. Escape to cancel"); the key hints are never repeated on X or Shift+Arrows, which say target, position, preview ("Rome, Rome city, 2 tiles east, valid target, Ranged strength 20 against 17, ..."; `PlotDescription_GetShort` option `targetInfo`); pad X = F13 walks the targets like the keyboard X); Shift+Arrows say "2 turns" / "unreachable" / "attack, 2 turns" (`GetMoveToPathEx`); Enter confirms (`MoveUnitToPlot`; direct `RangeAttack` / `AirAttack` / `CityCommandTypes.RANGE_ATTACK` requests; a real click for other modes); Escape cancels. Keys are always consumed; the mode resets when the unit dies, is deselected or the turn ends. Interface modes `MAKE_TRADE_ROUTE`, `TELEPORT_TO_CITY` (traders) and the `SPY_*` modes are chooser modes (`m_chooserModes`): the hub stays out of their way.
- **W = Attack:** ranged/air units enter their attack mode, melee units the move mode where only enemies are valid; jumps to the nearest enemy and reads the preview. The preview (`CombatManager.SimulateAttackInto`, `CombatText.lua`): "attack, 1 turn, Strength 20 against 17, deals 45 damage, target left with 2 of 100, you take 20", walls/city health/pillage/no combat, "would declare war on X" (`IsAttackChangeWarState`); Space lists modifiers; far targets say "Strength 33 against 15 when you reach it". The war dialog (`DeclareWarPopup.lua` override) is spoken and modal. No target: "No enemy in range of the X. Nearest enemy: ...".
- **X in attack modes** walks only attackable targets (`GetAttackTargets`, `GetCityAttackTargets`, melee: reachable hostile plots incl. cities/districts); hostile without war first, would-declare-war after; each target ends with "3 of 5" ("5 of 5, X wraps to the first" on the last). Ranged mode preselects a target. Modes that list their own plots (deploy, rebase, corps) walk those.
- **Results:** "Your Warrior attacks Barbarian Spearman: Spearman takes 28 damage, 8 of 100 left" (from `CombatVisBegin`; only within 3 tiles of own units/cities; a city kill is attributed from the fight just announced since the engine reports killer -1 for city shots). `StatusMessagePanel` drops the game's duplicate lines only when the hub spoke within 2 s. "Attacking X" precedes a city shot; "Attack under way" holds until the result.
- **Nukes:** strike mode by keys; Stand down and Escape in the confirm dialog say "Launch cancelled. Still in nuclear strike mode ...".
- Known gaps / unverified: "Launching" line before a real nuke; war-confirm cancel during a nuke strike; air Deploy/Patrol to a real carrier or airstrip.

## Settler, builder and activation browsers (X)

- **Settler** (`SettleScan.lua`, formula in its header): candidates = the advisor's 5 picks (`GetSettlementRecommendations`) plus every revealed land plot within 6 tiles that `SettleScan_CanFound` allows (own rules: min city distance, mountains, wonders, foreign borders; plus `CanStartOperation( unit, FOUND_CITY, plot, false, true )`, which says no for every plot at 0 moves, then "B to found next turn"). Score: fresh water/coast, resources weighted per ring (ring 1 = the six neighbours; each resource once; plots another city owns do not count), food/production, hills, hazards, crowding, barbarians, travel turns, advisor bonus; sites within 2 tiles of a better one merge. Selection says "Can settle here, but floods. Best: 1 tile south-west, 1 turn, river, coast, marble. X to browse." or "Here is good ..." / "Best spot is clearly better ..." (score-gap thresholds). Browser items add distance to the nearest own and foreign city; Space = all reasons and ring detail; Enter moves (or "B to found the city here"); Escape restores the cursor. Cursor text while a settler is selected ends "can settle" / "cannot settle: too close to Nazca". Reasons name only cities we have seen.
- **Builder** (`BuildScan.lua`, `HubSettle`): "Tiles to improve near Rome, 5 tiles"; items lead with the improvement ("Farm plus 1 food, 2 tiles north-east, Wheat, 1 turn, worked"); resource tiles first, then worked, then the rest; Left/Right switch city; Enter walks there (own tile: builds/menu; arrival builds with the danger guard); a "Later" group lists tiles that need a tech ("Mine needs Bronze Working", `ResourceTech.lua`). Yield changes are base values (no adjacency/policy bonuses).
- **Activation tiles** (great persons with `ActivationHighlightPlots`, archaeologists, naturalists, rock bands, completed-district targets): same browser; "Arrived. Enter activates".

Design and button map: `docs/controller-plan.md`. The console app polls XInput and injects keys (A Enter, B Escape, Y Space, stick arrows, D-pad Home/End/Tab, others F13-F24; a held LB/RB turns stick/D-pad up/down into PageUp/PageDown); `HubGamepad` (table `Gamepad.lua`, catcher in `WorldInput.lua`) interprets them by context; `HubPad` runs the LB/RB ring. Spoken hints name the pad button through `SRKey`, `SRPadHint`, `SRKbHint` (expanded by the console app, `KeyHints.cs`). Pad X on the bare map opens the selected unit's browser when it has one; lists advertise ", Y for details" once per open (pad only). In lists and in screens with their own Tab handling (tree, deal view, reports ...; `Gamepad.TranslateListKey` / `WrapInput`) the D-pad up/down move one item, right/left are Right/Left, LB/RB are the previous/next section or tab (LB/RB reach the screen while a game screen is open; Places treats its categories as sub-stops of the ring), and PageUp/PageDown (held bumper + up/down) jump to the previous/next group (production panel, Places "Your units" by type); see controller-plan.md, "In lists". Gaps: Options, save game menu, world congress, map search, advisor popup, front end screens without `KeyNavList` still get Home/End/Tab as keys.
