# Driving the game with civctl

`util\civctl.cmd <command>` (PowerShell script `util\civctl.ps1`; read its header for all options).

| Command | Does |
|---|---|
| `build` | ModBuddy build + deploy. Must print `1 succeeded`; exit code 1 otherwise. **Refuses while the game is running** (ModBuddy recreates the deployed folder, which kills hot reload until a restart); `stop` first, or `-Force` if you restart anyway. Times out (instead of hanging) if ModBuddy shows a dialog; then take a `shot`. |
| `stop` | Kills game + console app and waits for teardown. |
| `start [-Timeout 180]` | Starts the console app and the game, skips the intro movie, returns once "Main menu" is announced. |
| `key <Key> [-Count n] [-Settle ms] [-All]` | Focuses the game, sends the key as a hardware scancode, prints the screen reader lines it caused as `SR> ...`. Lines that arrived after the previous command show as `(earlier) SR> ...`. `-Settle` (default 600) is the MAXIMUM wait per press (use 1500-3000 for keys that open screens): the command returns as soon as an SR line has arrived and `-Quiet` ms (default 150, or 700 when `-Settle` >= 1500; an explicit `-Quiet` always wins) passed without another one; a key that says nothing waits the full `-Settle`. `-Quiet 600` for a late second line, `-NoQuiet` = the old fixed wait. With `CIVCTL_REPORT_WAITED=1` (the regress runner sets it) it also prints `@@waited <ms>`; with `CIVCTL_PROFILE=1` `@@profile init=ms health1=ms focus=ms pending=ms pre=ms send=ms wait=ms log=ms health2=ms total=ms` (phase times, ms). Key names are .NET `Keys` names: `Down`, `Up`, `Left`, `Right`, `Enter`, `Escape`, `Space`, `Tab`, `A`, `F1`... Chords: `Shift+E`, `Control+Shift+F` (Shift/Control/Alt + one key). |
| `sr [-All]` | Prints new screen reader lines (`-All`: every new `Lua.log` line, incl. `#KEYNAV_MOVE`). |
| `wait <regex> [-Timeout s]` | Blocks until a screen reader line matches (exit 1 on timeout). Use it instead of sleeps, e.g. `wait Begin Game -Timeout 240` (multi-word patterns unquoted: from Git Bash a quoted arg breaks cmd.exe; avoid `|` and `&` in patterns) during a game load. |
| `shot` | Screenshot of the game window (downscaled to 1280 px), prints the PNG path; view it with the Read tool. |
| `deploy` | Hot reload (first lints the changed `.lua` files with `util/lint.py`: errors refuse the deploy, a tool problem only warns, `-NoLint` skips): copies changed shipped files (.lua/.xml/.sql/...) from `ScreenReaderAccess\` straight into the deployed mod folder (in place; shrinking files are padded first so the game never reads a half-written file), the running game re-initialises the affected context within ~1 s. Prints `deployed <file>` per file and `LUA ERROR> ...` (exit 1) for errors (including `Syntax Error`, then also `CONTEXT FAILED TO LOAD ... <files>`) in the next 2.5 s. `key Backspace` is an alias of `Back`. Files the deployed folder lacks print `NEW FILE(S) not deployed: a, b -> civctl build + restart needed` (a new override file never loads until `build` + restart; also with `reload`); files deleted from the repo but still deployed and `Database\` changes print `needs build + restart` (all exit 3). |
| `reload <file...>` | Rewrites the named deployed files (path or name fragment, e.g. `reload InGameAccess.lua`) even if unchanged, to force the game to re-init that context. |
| `lua <state> <code>` / `lua <state> -File f.lua` | Runs Lua in a Lua state via FireTuner (needs `EnableTuner 1` + game restart). States: `civctl states`; useful: `GameCore_Tuner` (gameplay DB/players: set up scenarios, read units), `InGame`, `InGameAccess` (the hub's own state). Prints `print()` output; a single expression or a `return x` is printed like a REPL (`lua InGame 'Game.GetCurrentGameTurn()'`). `ERR:` + exit 1 on Lua errors, and `ERR: no completion within 8s` (exit 1) if the state hangs. State may be a name or an index (state indexes change when the game reloads contexts; prefer names). **Quoting:** from Git Bash use `util/civctl lua ...` (no `.cmd`), which keeps spaces and quotes intact; `civctl.cmd` loses double quotes inside arguments from PowerShell and breaks on quoted arguments from Git Bash, so with `.cmd` use single-quoted Lua strings, or `-File` for anything non-trivial. |
| `menu` | Is the in-game options menu or a popup/screen open? Prints `MENU: OPEN/closed` and `POPUP/SCREEN OPEN: ...`; exit 4 if either is open. |
| `states` | Lists tuner Lua states. |
| `status` | Game / console app running, lock holder, and `location: in game, turn N (civ, leader)` or `front end`. Reports a crash/hang (exit 5). |
| `save <name> [-Purpose "..."] [-Profile p]` | Named save of the running game (`Network.SaveGame` in `InGame`), copied to `test/fixtures/<name>.Civ6Save` with a sidecar `<name>.txt` (turn, civ, profile, purpose, mod commit). ~3 s. |
| `load <name>` | Loads a fixture (copies it into `Saves\Single` if needed). From in game it first runs `Events.ExitToMainMenu()`, then `Network.LoadGame` from the `MainMenu` state (calling it from `InGame` crashes the game), Enter at "Continue Game", waits for `Turn N`, closes the Gathering Storm intro of turn-1 saves. ~30-45 s. On a crash it restarts the game and retries once. |
| `endturn` | SETUP/VERIFICATION only. Requests the end of the turn the way the End Turn button does (`UI.RequestAction(ACTION_ENDTURN)` after checking `NotificationManager.GetFirstEndTurnBlocking` and `UI.CanEndTurn`; `util/civturn.py`). Refuses and names the blocker with the ActionPanel text and the enum (`"Unit needs orders" (ENDTURN_BLOCKING_UNITS) is pending`) when units need orders / research / production is pending. **Play-tests must end turns with Enter like a player** (that exercises the End Turn announcements and blockers). |
| `wait-turn <N> [-Timeout s]` | Waits (polling the tuner every 2 s, `-Timeout` default 120: raise it for long AI turns) until the game is at turn N and the local player's turn is active. Prints the `SR>` lines meanwhile. AI-turn popups (World Congress, era, ...) are REPORTED as `popup> ... open: X (not pressing keys...)`, never answered: look at the SR lines and close them yourself. Exit 1: timeout, or the game is already past N. |
| `clear-advisors` | Closes the advisor popups a loaded or tuner-changed game queues (they swallow keys): one tuner call each, `KeyNavActivate(1)` in the AdvisorPopup state while its context is visible (~1.7 s per popup), max 12. `load` runs it by default (`-KeepAdvisors` skips it; `-ClearAdvisors` is accepted as a no-op); the regress runner loads with `-KeepAdvisors` and uses its own `clear-advisors` step. |
| `key-release` | Releases Shift/Control/Alt on both sides. `key` with a chord already does this after every press; use it when the game acts as if Shift is stuck (Down does nothing, Tab goes backwards). `key Shift+Tab` is REFUSED (it opens the Steam overlay, which eats the key-up): use `Control+Tab`. |
| `fixture-info <name>` | Needs that fixture to be the loaded game (`load` writes `%TEMP%\civctl\loaded.txt`; the turn must still equal the sidecar's; `-Force` skips the check). Runs `util/fixture_facts.lua` in `InGame` (every section in pcall, `(n/a: ...)` marks a missing API: fix it there) and appends a `facts:` block to `test/fixtures/<name>.txt`: turn, era, gold/faith/favor, cities with districts and buildings, units by type, trade route slots, met civs and city-states, great people points, religion, spies, governors, pending blocker, visible hostile units within 6 tiles of our cities (type, owner, distance, city), unimproved resources in our cities' plots with the tech/civic that unlocks their improvement, seen barbarian camps (these three sections are unverified: rerun on the main fixtures and fix any `n/a`). Offline agents read it instead of guessing. |
| `fixtures` | Lists the fixtures with their sidecar data. |
| `newgame <profile>` | Creates a game from `util/profiles/<profile>.lua` (`early`, `crowded`, `medieval`, `industrial`, `modern`, `modes`; each fixes leader Trajan and both seeds, so the start is identical every time): Create Game, apply the profile in the `AdvancedSetup` state, `HostGame()`, Begin Game, Escape on intro/popups, then `save <profile>-start`. ~70 s. |
| `advance <n>` | SETUP/VERIFICATION only, **play-tests never use it**. Gets to turn X+n for a test: the game's own autoplay AI plays our civ for exactly n turns (`autoplay` underneath, same progress lines every 30 s, ~5-20 s/turn, run it in the background), so every blocker (production, research, civic, envoy tokens, commemoration, escape route, units that cannot skip) is resolved by the game's own AI logic, no hand-made operation parameters. Afterwards `civturn.py advance-check` verifies the counter moved by n (else exit 1), `wait-turn` waits for our turn, advisor popups are closed. The AI makes the choices, so the game differs from one you played; `-Save <name>` saves a fixture like `autoplay`. |
| `autoplay <n> [-Save name]` | The AI plays n turns for our civ (`InGame` state: `SetObserveAsPlayer(0)`, never OBSERVER), prints `turn N (k/n)` every 30 s (the tuner is polled no more often), fails after 25 s/turn, then saves the fixture. Run it in the background (it can take 30+ min). Hang detection tolerates 150 s (`-HangGrace`) while the log still grows. |
| `scenario <name>` | Runs `util/scenarios/<name>.lua` in `GameCore_Tuner` on a loaded fixture (22 scripts; `head -4 util/scenarios/*.lua` shows each header: fixture, status, keys to press; `util/scenarios/README.md`). Never save a scenario-modified game over a fixture. Advisor popups queued by a load or by the scenario swallow keys and `menu` does not list them: press Enter until no `ADVISOR:` line comes back. |
| `regress [name... or all or changed [--base rev]] [--share-load\|--no-share-load] [--no-batch] [--no-retry]` | Runs the speech regression scripts of `test/regress/*.txt` (~184 scripts; `python util/civregress.py`: load / scenario / key / wait / lua / clear-advisors / expect / expect-not / expect-lua / no-lua-errors; format in its docstring), prints PASS/FAIL per check with the real SR> lines; exit 1 on failure. `all` takes ~90 min. Details below. |
| `batch` | Reads one command per stdin line, a JSON array of civctl arguments (`["key","Down","-Settle","1500"]`), runs it like a normal command line (own script scope, same owner/lock refresh, log cursor, modifier release, exit codes) and prints its output followed by `@@CIVCTL-DONE <rc>`; prints `@@waited <ms>` for key/action. Used by the regress runner, not by hand. |
| `action <ActionId> [-Count n] [-Settle ms] [-Quiet ms] [-NoQuiet]` | Presses the CURRENT key of a game or mod hotkey: looks `<ActionId>` (e.g. `NextUnit`, `KeyNavCityReport`, `ToggleTechTree`; case-insensitive, also the display name) up in the user's `InputSettings.json`, else in the default gestures (mod `Database/*.sql`, game `InputConfiguration.xml`), then behaves exactly like `key` (same output, lock, owner, JAWS refusal). Unbound or unknown action: message, exit 1, nothing is sent. Use `action` for rebindable hotkeys (they survive a rebinding) and in `test/regress` scripts (`action KeyNavWhatsNext -Settle 1500`); use `key` for plain navigation keys of our own screens (Up, Down, Enter, Escape, Tab, letters in a menu). |
| `unlock` | Releases the lock. The lock is an owner lease: every command that drives the game takes `%TEMP%\civctl\lock` for `-Owner` / `$env:CIVCTL_OWNER` and KEEPS it between commands; without an owner the command is REFUSED (exit 7; in Git Bash prefix EVERY call, an export does not persist: `CIVCTL_OWNER=<your agent name> util/civctl <cmd>`). Another owner gets `game in use by X, last used N s ago` (exit 6) until the owner has been idle for 3 min (then it is taken over with a warning; long commands refresh the lease every 30 s). Run `unlock` when you finish. `unlock` needs no owner, so anyone can free a dead agent's lease; it prints whose lease it released. No owner needed: `build`, `menu`, `shot`, `keymap`, `status`, `fixtures`, `states`, `unlock`. |
| `keymap` | Regenerates `keymap.md` (below) from `InputSettings.json` + default gestures (`util/keybindings.py`). No game, no owner needed. |

`action <Id>` calls the same `Invoke-Key`/`Chord` as `key` (code-read, round 28): an `action` that works while `key Shift+Left` / `key Control+K` is silent means a different key was sent (check `python util/keybindings.py --key <Id>`; the user's InputSettings.json can differ from keymap.md) or the SR line came after `-Settle`; `key|action ... -Trace` prints every input event (`@@trace` vk/scan/flags/foreground window). Modifiers now get 60 ms before and 30 ms after the key.

### regress details

- Lock and owner: takes a run lock (`%TEMP%/civctl/regress.pid`; a second concurrent run is refused with exit 8, a dead pid is stale). Needs an owner (exit 7 without) and passes it to the civctl calls it makes. The runner talks to ONE long-lived `civctl batch` process (reads one JSON argument array per stdin line, runs it like a normal command line, prints its output plus `@@CIVCTL-DONE <rc>` and `@@waited <ms>` for key/action; not for use by hand); `--no-batch` goes back to one powershell.exe per step.
- New scripts: a fix agent writes a script for each fixed bug. First run of a script nobody has run against the game (blind-written): `regress <name> --record` (writes `test/regress/<name>.recorded.txt` with the SR> lines each expect saw; `--update` also rewrites the failing expect lines, original kept as `.bak`; review the diff) instead of trial and error.
- Stale-script search (no game): `python util/civregress.py --impact <old text>...` / `--impact-diff <rev>` (string literals removed from mod Lua in the diff) lists the `expect` lines (script:line) that match or contain them.
- Shared loads: `all` shares one load per fixture by default, but only after a reset check (one tuner call, `HubCore.TestResetState`: nothing open, hub in plain map mode, turn/gold/units/cities as after the load; it puts the cursor and selection back) says the game is clean; a dirty check just makes the next script load fresh. Selection, cursor, target/interface/lens mode, open screens and chooser side panels (research, civics ...), hub modes, production/research/civic/policy slots, government, founded religion and controller mode (the check switches it off, like F23) are covered by the check, so a script that only browses and closes needs no marker. `# own-load: <reason>` scripts (for scripts that check what the load itself says, e.g. the turn announcement) always load themselves; `# options: animations|advisor` scripts load themselves unless the previous game was loaded under identical options (such scripts run next to each other and share one load; the options are switched only when they change). `# no-share-load: <reason>` and scenario scripts may START on a clean shared game, but the next script loads fresh: give every script that changes game state the reset check cannot see that marker with a reason. `# dirty-group: <tag>` (instead of the marker) is for a set of scripts on one fixture whose invisible change is the same and idempotent (e.g. the tuner removing the two barbarians next to Rome in early-t60): they run one after the other on ONE load, the reset check still runs between members, the last member ends the sharing; a member that also carries `# no-share-load:` (it changes more) runs last in its group. `# was: <old names>` in a merged script lets `regress <oldname>` find it. A script that fails on a shared game is rerun with its own load. `--no-share-load` gives every script its own load.
- Retry and report: at the END of `all`/`changed` every still-failing script is retried once with a fresh load: a pass counts green and is listed as `FLAKY <name>` (TIMING + SUMMARY, both verdict lines printed), a second failure stays `STILL FAILING`; `--no-retry` disables. It ends with a TIMING table (BREAKDOWN: loads saved, reset-check time) and TOTAL. `all`/`changed` also write the TIMING + BREAKDOWN table plus a per-fixture load cost line (LOADCOST) to `%TEMP%\civctlegress-timing-<date>_<time>.txt` and `%TEMP%\civctlegress-last-timing.txt` (the path is printed): use it to see which fixtures cost the loads. `civregress.py all --dry-run` prints the simulated number of loads (every reset check clean).
- `changed` selection: each script has a `# covers: <glob>...` header. Core files (ScreenReader, KeyNavList, SRListen, KeyboardNavigation, InGameAccess, HubCore) select everything, except when the file's diff only adds single-line registrations (`include(...)`, `HubCore.AddEvent/Listen(...)`, `Hub.RegisterAction(...)`, `LuaEvents.X.Add/Events.X.Add(...)`), blanks or comments AND every registration names a module whose own file is changed in the same diff (`include("HubFoo")`, `HubFoo.OnBar` with HubFoo.lua changed: its covering scripts run instead; the ignored lines are printed verbatim; `--dry-run` prints "core file X: registration-only diff, ignored"). A multi-line handler body counts as a core change. Other `Hub*.lua` go by each script's `# covers:` (one harness failure once triggered two extra full runs, ~2 h lost).
- Verifier rule: after a mid-round fix rerun only the failing script(s) plus `regress changed`; `regress all` runs ONCE per round, at the end, after the last merge. Restart the game before a long regress run if it has been up for hours (stale state failed 23 checks in 5 scripts that pass on a fresh game).
- Regress `wait` window (harness behaviour): a `wait` step starts a fresh expect window (it is an action step) and scans only log lines printed after it begins: a line spoken during the preceding `action`/`key` settle is invisible to both the `wait` and the `expect` after it. Use a fixed `-Settle N -NoQuiet` on the action, then `expect` (prophet-u-founds does; the notification line comes ~1 s after U).


## Crashes, hangs and exit codes

`key`, `wait`, `sr`, `lua`, `save`, `load` check the game: a missing game process after a recent crash dump, or a running `FiraxisBugReporter.exe`, prints `GAME CRASHED` (with the dump path under `%LOCALAPPDATA%\Firaxis Games\Sid Meier's Civilization VI\dumps`) and exits 5; a window not responding for 8-25 s prints `GAME HUNG` (exit 5). Then: `stop`, `start` (kills a leftover reporter and says so), `load <latest fixture>`. Exit 6 = lock held by another owner; exit 7 = no owner given. `key` refuses `Add`, `Subtract`, `Multiply`, `Decimal`, `Insert`, `Clear` and `NumPad0-9` (JAWS keys).

## Save fixtures: policy

Fixtures are named saves in `test/fixtures/` (committed; each ~0.5-1 MB; sidecar `.txt` has the mod commit; regenerate one when it stops loading, e.g. `newgame <profile>`).

- A play agent that hits a bug runs `civctl save bug-<short-name> -Purpose "..."` right away (before working around it) and names the fixture in its report.
- A fix agent first loads that fixture and reproduces the bug, then verifies the fix by loading it again. "Verified by a direct call" is the exception.
- Test setup (tuner spawns, declared wars) happens in a game loaded from a fixture and is never saved over the play-through chain. The play-through keeps its own names: `pt-t10`, `pt-t20`, ...
- After a crash: `civctl load` the latest fixture, not the autosave.
- Never call `Network.LoadGame` from the `InGame` state (crash); `civctl load` does it right. Documents is OneDrive-redirected on this PC: civctl resolves it with `[Environment]::GetFolderPath('MyDocuments')`.

## Workflow

1. First time (or after new files / `.civ6proj` / SQL changes): `build`, then `stop` and `start`, load a game. After that, for Lua edits use `deploy` and keep playing: no restart. `build` refuses while the game runs (it would kill hot reload until the next restart). Timings: full loop build+stop+start+load a save ~65 s; `deploy` ~4 s.
2. Navigate by **reacting to `SR>` output**: press one key, read what was announced, decide the next key. Loop in PowerShell with a match condition when walking a list, e.g.
   ```powershell
   for ($i=1; $i -le 12; $i++) { $o = & util\civctl.cmd key Down; "Down -> $($o -join ' | ')"; if ($o -match 'Start Game') { break } }
   ```
3. After a run, grep `%LOCALAPPDATA%\Firaxis Games\Sid Meier's Civilization VI\Logs\Lua.log` for `Runtime Error` and your file name.
4. `stop` when done (the user may want the PC back).

## In-game hotkeys

`.claude/skills/civ-test/keymap.md` lists every action on the Options > Key Bindings tab with its action id (for `civctl action <Id>`), its key and the exact `civctl key` argument (e.g. Found City = `B`, Next Ready Unit = `OemCloseBrackets`, Form Army = `Control+Shift+F`). Do not read it whole: grep it, e.g. `grep -i "found city\|next ready" .claude/skills/civ-test/keymap.md`.

A new hotkey also needs a description in `Accessibility/HelpText.lua` (the Control+H help list; `test/py/test_helptext.py` fails without it for `KeyNav*` actions); regenerate this file with `civctl keymap` to see it here.

It is generated, not hand-written, and needs no running game: `util/keybindings.py` reads the user's `%LOCALAPPDATA%\Firaxis Games\Sid Meier's Civilization VI\InputSettings.json` (their real bindings) and, for actions missing from it (a freshly added mod action), the default gestures of `ScreenReaderAccess/Database/*.sql` and the game's own `InputConfiguration.xml` (read-only). Run `util\civctl.cmd keymap` after rebinding keys or editing `Database/*.sql` hotkeys; `python util/keybindings.py [--json] [ActionId]` prints one binding. The file lists unbound actions, keys the harness must never send (JAWS reserved: NumPad Add/Subtract/Multiply/Decimal, Insert, ...; `Toggle2DView` is the main-keyboard `=` key = `OemPlus`, not NumPad plus) and duplicate bindings (one key, several actions) at the top. Prefer `util\civctl.cmd action <ActionId>` over `key` for these hotkeys, so scripts keep working after a rebinding.

## Never send NumPad + / - (civctl `Add` / `Subtract`)

They are JAWS commands: `Subtract` turns the JAWS cursor on, after which arrow keys, Home, End etc. no longer reach any window (the game never sees them, even from SendInput; it survives a game restart). `Add` (NumPad plus) turns it off again. Use the main keyboard keys `OemPlus` / `OemMinus` instead.

## Escape and the in-game menu

Escape with no popup or mode open opens the in-game options menu (`In game menu` / `RETURN TO GAME`), and the next Down+Enter then does something real (Quick Save...). Before a key sequence that starts with Escape, run `util/civctl menu`: `MENU: OPEN` means Escape will close it, `closed` means Escape will open it. To back out: `key Escape` once while `MENU: OPEN` (announces `RETURN TO GAME`), then `menu` again to confirm. The `POPUP/SCREEN OPEN` line lists open screens (e.g. `PartialScreens/CityStates`); close those with Escape too.

## Tuner recipes

Run with `lua GameCore_Tuner '<code>'` (`-File` for longer scripts). Recipes (spawn units, finish research, meet civs, save/load/setup/autoplay snippets), which APIs exist in which tuner state and how to trigger popups are in `docs/engine-notes.md` section "Tuner recipes" (and "Tuner and test setup"). `UI.SelectUnit` works from the `InGameAccess` state only (not GameCore_Tuner).

Harness facts:

- `civctl lua` does not print the SR> lines it causes; they show up as `(earlier)` lines in the next `key`/`sr`.
- Advisor popups (queued after a load, first contact, a governor point, envoys) swallow keys and are not listed by `civctl menu`; Enter closes one at a time (`clear-advisors`, also a step in regress scripts).
- Only one tuner connection at a time (`util\civtuner.py`); state indexes change on context reload, use names.

## Common paths (may be outdated)

- Main menu opens with focus on Single Player. `key Enter` opens the submenu (announces Resume Game if a save exists, else Load Game); Down until `Create Game`; `key Enter -Settle 3000` → `CREATE GAME`.
- On Create Game, Up from the first item wraps to `Start Game`; Down reaches `ADVANCED SETUP`.
- After Start Game: `wait Begin Game -Timeout 240`, then `key Enter -Settle 3000` begins the game.
- Exit: Up from Single Player to `Exit to Desktop`, Enter, the popup announces and focuses `OK`, Enter.

## Tips

- Screenshots are not routine: do not `shot` after keys. Take one only for the UI you are actively building, or when the SR> output is unexpected and unexplained.
- Token cost: `key`/`sr` output is ~10-30 tokens per press; a screenshot is ~1-1.5k. Screenshot only when the announcements don't explain what happened.
- `Lua.log` shows what the mod printed, not what the console app actually spoke.
- Don't use Bash `sleep` to wait on the game; use `wait`, or a PowerShell loop polling `Lua.log` for a pattern.
- The user can't use their PC while you drive the game (focus and mouse are taken over).

## Test game options (speed)

`python util/testopts.py on` sets test-friendly user options (advisor disabled, QuickCombat/QuickMovement, no combat camera look-at, no historic moment animation) after saving the user's real values to `%TEMP%\civctl\testopts-backup.json` (never overwritten by a second `on`); `restore` writes them back and deletes the backup; `status [--json]` shows both. Setup agents run `on` before `advance`/`autoplay` for speed and `restore` after. `regress` does both itself unless `--real-options`; a script header `# options: animations` and/or `# options: advisor` runs that script with those options at the user's values. After a crash or killed run: `python util/testopts.py restore`.

The user's game runs the low graphics preset + `EnableAsserts 0` permanently (applied 2026-10-26, originals in `%TEMP%\civctl\perf-backup`): about -17% load time; AI turn speed is CPU bound and unchanged; `LoadGameTickIntervalInMS`, `UIOnlyRendering` and `AddMinimapSnapshotToSaves` gave nothing measurable.
